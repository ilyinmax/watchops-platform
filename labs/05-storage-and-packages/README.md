# Тема 05 — Пакеты, диски, файловые системы и архивы

## Цель

Научиться диагностировать заполнение файловой системы, различать использование дисковых блоков и inode, находить большие файлы и удалённые файлы, которые продолжают удерживаться процессами, а также безопасно создавать и проверять архивы логов.

## Что было изучено

### Устройство хранения Linux

Разобрана цепочка:

`устройство → раздел → файловая система → точка монтирования → файлы`

Корневая файловая система лабораторной VM:

* устройство: `/dev/sda2`;
* файловая система: `ext4`;
* точка монтирования: `/`.

Для диагностики использовались:

* `lsblk` — просмотр блочных устройств;
* `findmnt` — просмотр точек монтирования;
* `df` — состояние файловой системы;
* `du` — использование пространства файлами и каталогами.

## `df` и `du`

`df` показывает использование блоков всей файловой системы.

`du` считает место, занимаемое доступными через дерево каталогов файлами.

Был воспроизведён сценарий, в котором файл удалён, но процесс продолжает держать его открытым.

После удаления файла:

* `du` перестал учитывать его размер;
* `df` продолжал показывать занятое место;
* `lsof +L1` обнаружил удалённый открытый файл;
* после корректного завершения процесса файловый дескриптор закрылся и место освободилось.

Это показывает, почему удаление большого файла не всегда сразу возвращает свободное место файловой системе.

## Sparse-файлы

Был создан разреженный файл размером 300 MiB.

Его логический размер составлял 300 MiB, но фактически блоки файловой системы практически не использовались.

Для сравнения использовались:

```bash
ls -lsh
du -h
du --apparent-size -h
```

Вывод: логический размер файла и реально занятое им дисковое пространство могут различаться.

## Inode

Файловая система ограничена не только количеством свободных блоков, но и количеством inode.

Был создан стенд с 5000 пустых файлов. Данные почти не занимали дискового пространства, но каждый отдельный файл использовал inode.

При ошибке:

```text
No space left on device
```

необходимо проверять как свободное место:

```bash
df -h /
```

так и inode:

```bash
df -i /
```

Если inode закончились, причиной может быть большое количество небольших файлов.

## Поиск занятого пространства

Для поиска крупных каталогов использовалась диагностика сверху вниз:

```bash
du -xhd1 / | sort -h
```

После определения крупного каталога команда повторяется уже для него.

Для поиска конкретных крупных файлов использовались `find`, сортировка по размеру и `numfmt`.

В лабораторном стенде был найден файл:

```text
space-lab/beta/data/store.bin
```

размером около 700 MiB.

## Удалённые открытые файлы

Для поиска файлов, которые удалены из дерева каталогов, но остаются открытыми процессами:

```bash
lsof +L1
```

Перед завершением процесса необходимо определить:

* какой процесс удерживает файл;
* его PID;
* размер удерживаемого файла;
* чем управляется процесс;
* безопасно ли его перезапускать.

В случае systemd-сервиса корректнее управлять сервисом через `systemctl`, а не случайно завершать отдельный PID.

## APT

APT получает информацию о пакетах из настроенных репозиториев.

Разница между основными операциями:

* `apt update` — обновляет локальный индекс доступных пакетов;
* `apt upgrade` — обновляет установленные пакеты;
* `apt install` — устанавливает пакет и необходимые зависимости;
* `apt-cache policy` — показывает установленную и доступную версии пакета и его источник.

В лаборатории пакет `lsof` уже был установлен из репозитория Ubuntu `noble/main`.

## Архивирование

Для упаковки и сжатия логов использовались `tar` и gzip.

Архив:

```text
archives/watchops-logs.tar.gz
```

содержит тестовые логи WatchOps.

Содержимое архива проверялось командой:

```bash
tar -tzf archives/watchops-logs.tar.gz
```

Также выполнялось реальное восстановление в отдельный каталог и побайтовое сравнение файлов.

Основной принцип:

> Сначала создать архив, проверить его и выполнить тестовое восстановление, и только после этого удалять оригинальные данные.

* использование дискового пространства `/`;

Пример запуска:


## Диагностика заполненного диска

Базовый порядок расследования:

1. Проверить `df -h`.
2. Проверить `df -i`.
3. Найти крупные каталоги через `du`.
4. При необходимости найти самые крупные файлы через `find`.
5. Если `df` и `du` заметно расходятся — проверить `lsof +L1`.
6. Определить процесс, удерживающий данные.
7. Исправить первопричину безопасным способом.
8. Повторить проверки и доказать, что место освободилось.

## Важный нюанс прав доступа

Команда:

```bash
du -ahx / 2>/dev/null
```

не получает дополнительных прав.

`2>/dev/null` только скрывает ошибки `Permission denied`, поэтому итоговый отчёт может быть неполным.

Для полного административного анализа системных каталогов может потребоваться запуск `du` с необходимыми привилегиями.
