# Тема 02 — Потоки, перенаправления и обработка текста

## Что сделано

В лаборатории создан набор тестовых логов WatchOps и выполнен их анализ средствами Linux shell.

В ходе работы использовались:

* стандартные потоки `stdin`, `stdout`, `stderr`;
* перенаправления `>`, `>>`, `<`, `2>`;
* pipe `|`;
* `cat`, `head`, `tail`, `grep`, `cut`, `sort`, `uniq`, `wc`;
* `find` и `xargs`;
* `awk` и `sed`;
* exit codes;
* логические операторы `&&` и `||`.

Итоговый отчёт сохранён в:

`reports/final-report.txt`

Ошибки самой обработки сохраняются отдельно в:

`reports/command-errors.txt`

## Как строился отчёт

Обработка логов выполнялась как последовательный pipeline:

`логи → фильтрация по времени → только ERROR → исключение noise.local → статистика`

Для периода `2026-08-07T11:00:00–2026-08-07T11:05:00` были выбраны только события уровня `ERROR`.

После этого известный шум от `noise.local` был исключён.

Отдельно была построена статистика:

* количества ошибок по `target`;
* количества ошибок по HTTP `status`.

Итог:

```text
2026-08-07T11:01:20 ERROR target=example.org status=503 latency_ms=1988
2026-08-07T11:03:00 ERROR target=github.com status=500 latency_ms=950
2026-08-07T11:05:00 ERROR target=example.org status=503 latency_ms=2100
      2 target=example.org
      1 target=github.com
      2 status=503
      1 status=500
```

## stdin, stdout и stderr

Каждый процесс может использовать три стандартных потока:

* `stdin` — стандартный ввод;
* `stdout` — обычный результат работы программы;
* `stderr` — диагностические сообщения и ошибки.

Pipe:

```bash
command1 | command2
```

передаёт `stdout` первой команды в `stdin` второй.

Перенаправление:

```bash
command > file
```

записывает `stdout` в файл с перезаписью.

```bash
command >> file
```

дописывает `stdout` в конец файла.

```bash
command 2> errors.txt
```

направляет `stderr` отдельно.

Если нужно применить перенаправление ко всему pipeline, команды можно сгруппировать:

```bash
{
  command1 | command2
} > output.txt 2> errors.txt
```

## Exit codes

После выполнения команда возвращает exit code.

Основной принцип:

* `0` — успешный результат;
* ненулевое значение — другой результат или ошибка.

Для `grep`:

* `0` — совпадение найдено;
* `1` — совпадений нет;
* другие значения могут означать ошибку выполнения.

Код последней команды можно посмотреть через:

```bash
echo $?
```

## Диагностическая поломка

Был исследован сломанный pipeline:

```bash
awk '$2 == "ERROR" {print $3}' logs/*.log \
  | grep 'github.com' \
  | grep -v 'github.com' \
  | sort \
  | uniq -c
```

Симптом — итоговый результат был пустым.

Pipeline проверялся последовательно слева направо.

После первого:

```bash
grep 'github.com'
```

данные присутствовали:

```text
1 target=github.com
```

Следующая команда:

```bash
grep -v 'github.com'
```

исключала те же строки, которые предыдущая команда только что оставила.

Root cause — противоречащие друг другу фильтры.

После удаления лишнего отрицательного фильтра результат восстановился.

Главный вывод диагностики: длинный pipeline следует проверять по частям и определять, после какого конкретного этапа исчезают или искажаются данные.
